# Word 导出与 Render 部署

Word 导出采用上传、后台生成、下载三个步骤。前端将 JSON 数据作为 multipart 文件上传到 `POST /api/export-word-jobs?requestKey=...`，服务端直接写临时文件并返回 `202`。前端轮询 `GET /api/export-word-jobs/:id`，完成后下载 `/api/export-word-jobs/:id/download`。下载失败可重试同一文件，不会重新生成文档。

每个实例同时只生成一份 Word，最多接收三个未完成任务。每份文档由独立 Node 子进程生成，完成后退出，释放内存。模块层级文档和完整说明书按段落及表格批次生成后合并，保留完整表格、图片引用和可编辑标题编号；新疆模板逐段序列化 XML。最终 ZIP 流式写入磁盘，下载通过文件流发送。

- `WORD_EXPORT_WORKER_HEAP_MB`：生成进程的 V8 老生代堆上限，默认 192 MB。这不是整个实例的内存上限，图片、压缩缓冲区和 Web 进程还需额外内存。
- `WORD_EXPORT_MAX_UPLOAD_MB`：每次导出数据上传上限，默认 64 MB，包含 base64 图片。超过上限返回明确的 413 提示。
- 单次生成最多 20 分钟；生成完成的文件保留 15 分钟，过期后自动清理。任务及文件不跨实例共享，部署或重启会丢失；客户端最多自动恢复一次。多实例部署需使用共享队列和文件存储。
- 旧的 `POST /api/export-word` 仍可调用，共用同一生成队列。新页面使用后台接口，避免一直等待生成响应。

排查 Render 502 时，先检查同一时刻的服务日志是否有内存耗尽、进程退出或健康检查失败。完成日志记录生成进程峰值 RSS 和 Web 主进程 RSS。若生成失败但 Web 服务仍正常，页面应显示任务错误，而非网关 502。大量其他业务同时运行时仍可能需要更大的实例内存。

验证：`npm run test:word-export` 覆盖三个模板各 1,111 个功能过程及图片、下载重试、重复提交、队列上限、取消、过期清理、健康接口响应及旧接口。`npm run test:word-export:large` 使用每张约 24 KB、内容不同的 PNG，验证约 36 MB 上传数据。测试仅使用本机服务和合成数据，不调用模型或真实数据库。
